# トラブルシューティング

## ターミナル終了・途中失敗

新しい Bash からリポジトリルートへ移動し、set +eu、source scripts/local/common.sh、require_password、dc ps -a を実行する。Terraform OutputからIDとURLを取り直す。前の変数を再利用しない。初回setup途中で失敗した場合は State と Volume を確認して、成功した工程を繰り返さず失敗工程から再開する。

### 初回setup途中で停止した場合

- Stateが存在しないのにVolumeが存在する場合、bootstrapが未完了か、State消失かを確認する。自動で再構築しない。必要なら既存Stateのバックアップから復旧する。Dockerの一覧取得エラーは「新規環境」として扱わない。docker info と docker volume ls を先に確認する。
- Bootstrapが成功済みの場合、Secret登録、ZIP配備、Plan、Apply、ユーザー登録、Frontend配備のうち未完了の工程から実行する。
- Terraform Apply前にZIPが失敗した場合、表示されたバックアップ先のZIPとtfvarsを照合し、復旧方法を決める。古いZIPを無条件に再配備しない。lambda-build.ok がない、またはSHA-256が不一致の場合は build.sh lambda を成功させてから配備する。ZIPのアップロード先は /app/backend-source/build/distributions で、Frontendの配備元は /app/frontend-source/dist。旧マウントが残る場合は環境構築手順の既存環境引継ぎを実行する。

## API Gateway 502

```bash
source scripts/local/common.sh
require_password
dc logs --tail=200 floci
aws_test lambda get-alias --function-name music-app-local-api-handler --name live
aws_test lambda get-function-configuration --function-name music-app-local-api-handler --qualifier live --query '{State:State,Runtime:Runtime,LastUpdateStatus:LastUpdateStatus}'
```

ZIP、Version/Alias、Secret実値、PostgreSQL、Lambda初期化ログ、API Gateway統合先を確認する。修正後、health と認証・DB疎通を確認する。Issue #37で記録されたOPTIONS 502は実環境で再確認する。

## CORS

Terraform frontend_origin とDistribution ID、Flociの FLOCI_SECURITY_EXTRA_CORS_ALLOWED_ORIGINS、BackendとLambdaの FRONTEND_ALLOWED_ORIGINS を確認する。start.sh は設定が不一致の場合に確認を経てFlociを再作成する。旧コンテナに新しいマウントがない場合も同様。再作成前に新規ジョブ停止・処理完了を確認する。

## Terraform差分

```bash
bash scripts/local/terraform.sh check
```

終了コード2は差分あり。同期漏れ、tfvars、State、Flociの実リソース、Provider互換性を確認する。削除・置換が予期されない場合はApplyしない。Stateだけを消さない。既存Project・Volumeを変更しない。

## Dockerイメージ取得失敗

```bash
docker info --format '{{.ServerVersion}}'
curl -4 -I --connect-timeout 10 https://registry-1.docker.io/v2/
```

HTTP 401はレジストリ到達の目安。Timeoutはネットワークを先に調べる。Volume削除で解決しようとしない。

## Worker切替

worker-mode.sh status とMapping状態、Local Workerコンテナを確認する。Mapping Disabledと実行中ジョブ終了を確認するまでLocal Workerを起動しない。切替中は新規ジョブ登録を停止する。Local Workerへの切替はMapping Disabledと処理中ジョブ終了の確認後、Runtime Config/CloudFront配備を成功させ、Mapping Disabledを再確認してからLocal Workerを起動する。配備失敗時にはLocal Workerを起動せず、状態を確認して失敗工程から再開する。両方が動いていた場合は新規ジョブを止め、Local Workerを停止してから状態を調査する。

## 旧Shell環境

移行前のファイルは Git の 5d8ea29e00804fb6523a89aba5cbf57fd933ea25 に存在する。旧環境の復旧が必要な場合は別worktree等にその版を用意し、従来のProject名・Volume・ポートを明示して使用する。標準環境に旧Stateを適用しない。旧データは自動移行しない。

## Secret/Cognito検索失敗

登録前の検索が失敗した場合はFlociの稼働、対象Pool/Secret、権限、通信状況を確認する。既存Secretの実値更新は確認入力が必要。既存Cognitoユーザーのパスワードは自動リセットしない。新規ユーザー作成後にパスワード確定処理だけ失敗した場合はユーザー状態を確認し、意図した対象に対して手動復旧する。パスワード・TokenはログやGitに残さない。

## Runtime Config検証失敗

`bash scripts/local/terraform.sh output`、`bash scripts/local/export-frontend-config.sh` で、適用済みのAPI URL、Workerモード、診断フラグとの一致を確認する。生成済みJSONを手動編集して不一致を回避しない。
