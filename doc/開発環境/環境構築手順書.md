# 開発環境構築手順書

## 1. 前提

Linux / WSL、Docker Engine、Compose v2、Bash、Git、curl、flock を利用する。リポジトリ直下で各 Shell を別プロセスとして実行する。親ターミナルで set -e を有効化しない。

```bash
set +eu
git branch --show-current
git status --short
docker version
docker compose version
```

DB パスワードは既存 DB では初回の値を使用する。Shell が必要に応じて対話入力する。環境変数 TEST_DB_PASSWORD を使う場合は、次のように入力し、作業終了後 unset する。

```bash
read -rs -p 'DB password: ' TEST_DB_PASSWORD; echo
export TEST_DB_PASSWORD
```

## 2. 初回と既存環境の区別

```bash
docker volume inspect music-app-terraform-test_terraform_test_postgres_data music-app-terraform-test_terraform_test_floci_data
ls -l .docker-cache/terraform-test/terraform/local/terraform.tfstate
```

両 Volume と State がない新規環境のみ setup.sh を使用する。両方ある場合は既存環境として扱う。片方だけある場合は中断し、トラブルシューティングを参照する。旧 Shell 環境（music-app 等の Project 名）の DB、S3、Cognito、SQS は自動移行しない。必要データを先に退避すること。

### 初回構築

```bash
bash scripts/local/setup.sh
```

処理順: ディレクトリ準備、Terraform同期、PostgreSQL/Floci、ZIP・Frontendビルド、Init/Validate、Bootstrap Plan/Apply、DB Secret、ZIPアップロード・ハッシュ更新、全体 Plan/Apply、Cognito ユーザー、CORS・Runtime Config・起動、Frontend 配備、check。各 Plan を確認し、意図しない差分があれば承認しない。失敗時に最初から再構築しない。

### 既存環境の引継ぎ（Issue #35〜37）

旧ファイル名 docker-compose.terraform-test.yml は廃止済み。Project名、Volume、State、ポートは維持する。既存 tfvars は例示ファイルで上書きしない。必要に応じて既存の frontend_origin=http://localhost:5174、floci_host_url=http://localhost:4567、enable_runtime_infrastructure=true、enable_frontend_delivery=true を確認する。

```bash
bash scripts/local/start.sh infrastructure
bash scripts/local/build.sh terraform
bash scripts/local/build.sh lambda
```

既存Flociには新しいマウントがないため、次の操作を最初の一度だけ行う。新規ジョブ登録を停止し処理中ジョブの終了を確認してから実行する。DBとFlociのVolumeは削除しない。

```bash
source scripts/local/common.sh
require_password
dc --profile worker-local stop worker-local
dc up -d --no-deps --force-recreate floci
```

Floci の疎通が確認できてから続行する。既存環境では ZIP 更新、Terraform Plan/Apply により新しい Output と診断フラグを反映する。既存 Secret とユーザーは不用意に再作成しない。

```bash
bash scripts/local/upload-lambda-artifacts.sh all
bash scripts/local/terraform.sh plan
bash scripts/local/terraform.sh apply
bash scripts/local/build.sh frontend
bash scripts/local/start.sh all
bash scripts/local/deploy-frontend.sh
bash scripts/local/check.sh
```

既存 Worker モードが local なら start all の前に worker-mode.sh lambda で切替を行うか、worker-local モードで起動する。

## 3. 日常の起動・停止

| モード | コマンド |
|---|---|
| infrastructure | bash scripts/local/start.sh infrastructure |
| frontend | bash scripts/local/start.sh frontend |
| backend | bash scripts/local/start.sh backend |
| worker-local | bash scripts/local/worker-mode.sh local → bash scripts/local/start.sh worker-local |
| lambda | bash scripts/local/worker-mode.sh lambda → bash scripts/local/start.sh lambda |
| all | bash scripts/local/start.sh all |
| 停止 | bash scripts/local/stop.sh |

worker-local / lambda / all は Mapping 状態を確認する。切替中は新規ジョブを登録せず、処理中ジョブ終了を確認する。停止はコンテナのみ。Volume・State・S3・DBを保持する。

## 4. 個別ビルド・配備

```bash
bash scripts/local/build.sh frontend
bash scripts/local/build.sh backend
bash scripts/local/build.sh lambda
bash scripts/local/build.sh terraform
```

Frontend ビルドは npm ci / lint / tsc / vite。Backend は classes / test。Lambda は clean buildLambdaZips（API・Worker ZIP と依存関係分離確認）。Terraform は pull / sync / init / validate。ビルド中は共有出力先を使う常駐プロセスを停止する。

React更新後:

```bash
bash scripts/local/build.sh frontend
bash scripts/local/deploy-frontend.sh
bash scripts/local/start.sh frontend
```

Java更新後:

```bash
bash scripts/local/build.sh backend
bash scripts/local/build.sh lambda
bash scripts/local/upload-lambda-artifacts.sh all
bash scripts/local/terraform.sh plan
bash scripts/local/terraform.sh apply
```

APIだけ更新する場合は upload-lambda-artifacts.sh api、Workerだけなら worker。バックアップ先を記録する。ビルドが失敗した場合は以前のZIPを配備しない。

Terraform変更後:

```bash
bash scripts/local/terraform.sh sync
bash scripts/local/terraform.sh init
bash scripts/local/terraform.sh validate
bash scripts/local/terraform.sh plan
bash scripts/local/terraform.sh apply
bash scripts/local/terraform.sh check
```

check は差分なし=0、エラー=1、差分あり=2。Plan の削除・置換は通常の apply で拒否する。同期は .tf のみ、State・tfvars・Provider Lockを保持する。古い .tf 削除時は確認する。

## 5. Secret・Cognito・Runtime Config

```bash
bash scripts/local/put-db-secret.sh
bash scripts/local/seed-cognito-user.sh
bash scripts/local/export-frontend-config.sh
bash scripts/local/deploy-frontend.sh
```

Secret は music-app/local/db。既存DBパスワードと一致させる。Terraform State/tfvars に実値を登録しない。Cognito既存ユーザーのパスワードは再実行で更新しない。公開Configにパスワード・Token等を含めない。Workerモードと診断フラグはTerraform Outputから生成する。診断フラグ変更後は Backend を再作成し、Runtime Configを再配備する。
